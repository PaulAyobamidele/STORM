# MedTimer — how the per-SUT template fitted

One row per template hole (`notes/template_guide.md`): **fitted as-is**,
**adjusted** (how), or **did not fit** (why). Filled as each hole is met;
started 2026-09-28 in phase B. Holes 22 to 37 are filled in phases C and D.

| hole | file | verdict | what happened |
|---|---|---|---|
| 1 | types | **adjusted** | `ItemId` became `MedicineId` with ONE value. The template wants two or three entries of the SUT's own shipped data; MedTimer ships none, the tester creates the medicine in the prelude, so a second value would only multiply prelude steps. Kept as a type so every channel still carries provenance. |
| 2 | types | **did not fit** | `Scope` deleted: there is no external source, nothing a read could be directed to. |
| 3 | types | **did not fit** | `Context` deleted: a dose lands nowhere but on its medicine; no bucket to choose. |
| 4 | types | **did not fit** | `RecordId` deleted: at most one record per day per reminder, identified by the medicine itself (`DELETE (id)`, `EDIT (id, act)`). |
| 5 | types | **did not fit** | `Value` deleted: MedTimer has no per-item value to read back; the read-back is the state band and the row state, both on `CONFIRM`. |
| 6 | types | **adjusted** | `StateBand` became `StockBand` S0..S4 that moves DOWN on a committed take (`down`) and UP on a refund or correction (`up`); the template's band only grows. Saturating at S4 = four or more, one rung ABOVE the fixture's three units: the first draft saturated at the fixture's own rung and the compiled label list showed that an unjustified refund (three to four units) would then classify as the same rung and pass unseen. |
| 7 | types | **did not fit** | `value_of` / `item_of` deleted with holes 4 and 5. |
| 8 | types | **did not fit (by decision)** | SUT-initiated journeys (the reminder firing, the notification) are not modelled in the first sweep: the overview lets the tester act on a scheduled dose without any alarm, and the alarm path is inexact and slow (`observed_behaviour.md` §7). |
| 9 | types | **fitted as-is** | one `Route`, `rt_home`, the launcher activity. |
| 10 | types | **adjusted** | `Element` drafted from the source (screen anchors, the two oracles `el_state_button` / `el_med_card`, the four owed-but-absent error elements); every selector is confirmed against the live dumps in phase C. |
| 11 | types | **adjusted** | `ConcreteValue` drafted the same way; the prelude needs more typed values (name, time, dose, stock, unit) than a search-based SUT. |
| 12 | fixture | **adjusted** | `defaultItem` became `defaultMedicine`; the fixture's concrete content (three units, unit "pills", dose "1", a reminder late in the day) lives in `concrete_domain.yml`, and the spec's initial band `S3` encodes it — a tester assumption the header states, since the template's natural zero (no records) has no analogue for a stock. |
| 13 | fixture | **did not fit** | `defaultContext` deleted with hole 3. |
| 14 | fixture | **did not fit** | `defaultRecord` deleted with hole 4. |
| 15 | spec | **adjusted** | USER has six journeys instead of the template's five: create a medicine (valid / invalid), forbid skipping (`NO_SKIP`, a tester input that replaces a second fixture medicine), act on the dose, delete the record, correct the record, re-read. The fault observables sit where the template puts them: `WRITE_ERROR_SHOWN` as an alternative after `ACT`, `DB_CORRUPT_DETECTED` / `INFRA_STORAGE_ERROR` as the `by` arm of a disrupt around the re-read. |
| 16 | spec | **fitted as-is** | APP places the write-failure faults as siblings of the commit under `ACT` (WRITE-PATH), `APP_CACHE_STALE` before `ACT` (PRE-ARMED), the two read faults as interrupts of `VIEW`. |
| 17 | spec | **adjusted** | DATABASE keeps two extra state variables the template does not need: the dose row's `state` (PENDING / TAKEN / SKIPPED / ABSENT), because delete and edit change the stock depending on what the record was, and `skippable`, set by `NO_SKIP`. Journeys are guarded on the state (`ACT` while PENDING, `DELETE` / `EDIT` while a record exists) with the template's `if … else stop` idiom. `UE_KILL` keeps the template's "whole or nothing" pair. `DB_EVENT_LOSS` is a standalone state change (no template shape). |
| 18 | spec | **fitted as-is** | DISRUPTOR offers the eight faults, no `i`, no gated cascade. |
| 19 | purposes | **adjusted** | one file per fault as the template says, plus four parameter-borne purposes (`input_invalid`, `cannot_skip`, `delete_skipped`, `edit_flip`) that are two-step journeys rather than a single channel value; their names go into `disruption_mapping.yml` with `timing: none` so the walker knows the target needs no injection (phase E). |
| 20 | .io | **fitted as-is** | six parameterised inputs with `.*`, eight exact fault lines; `WAIT_FOR`, `OBSERVE`, `CONFIRM` and the four `*_SHOWN` / `*_DETECTED` / `*_ERROR` outputs left out. |
| 21 | generate script | **fitted as-is** | only the purpose list changes (phase E). |
| 34 | disruption_mapping | **fitted as-is** | the Android platform block: package, `databases/medTimer`, a reset script (`seed.sh`: `pm clear` plus the notification-permission grant; the fixture is created by the prelude, not seeded). |
| 35 | disruption_mapping | **adjusted** | one mechanism per fault as the template asks, but every write-path fault is `gate`, not `pre`: the fixture is created inside the walk, so a `pre` arming would break the prelude. The SI places each fault gate before the commit tap so the injection still precedes the write. The storage-full ballast fills the partition completely; the template's 20 MB headroom lets a SQLite page through. The template's Android schema had no verify probes; the injector was extended (SUT-agnostically, with a self-test) to read `verify_injected` / `verify_restored` and to answer `manifested()` from them. |
| 36 | disruption_mapping | **did not fit** | MedTimer has no cache; the stale-view purpose is realised by the SI (`timing: none`) as a Medicine-tab read before the write and a re-read after it, which tests cross-screen consistency rather than a cache. |
| 37 | disruption_mapping | **fitted as-is** | the honest expectation per fault is in the file's footer, copied from the behaviour note before any run. |
| 22 | SI | **adjusted** | two screens instead of the template's four: SCR_HOME (the overview, the launch screen and where every relaunch lands) and SCR_MEDICINES (the list). The edit and settings screens are passed through but never left on, because the bottom tab restores the last screen shown in it (confirmed live): every excursion returns to the list before the tab is left, so the funnels stay two-way. |
| 23 | SI | **did not fit** | there is no search; the "find the item" interaction is a fixed row on the overview (`el_dose_row`) and a fixed card on the list. |
| 24 | SI | **adjusted** | the value is read in two places: the row's state button (content description) on the overview and the stock text on the medicine card. Both are `observe`d before `CONFIRM`, which carries both. |
| 25 | SI | **adjusted** | after a commit the app stays where it is (the popup closes, the row re-renders); the SI reads the row, then switches tab to read the stock. After the kill `navigate (rt_home)` relaunches on the overview and IS the kill. The write-failure arms do NOT relaunch: the dose's writes run in a background broadcast after the tap, and a relaunch right after the tap killed the app before the broadcast was delivered (first sweep, confirmed in logcat), so the fault on the second write was never exercised; the observe's timeout is the time the app gets, and a crash fails that observe too. |
| 26 | SI | **adjusted** | the app refuses nothing: the empty name is accepted (live). The SI observes the error line the dialog's text field would show (`el_name_error`); its absence is the FAIL. For the forbidden skip the app WITHHOLDS nothing either (live), so the SI taps Skipped and reads the state back; a compliant app would make that tap impossible (no verdict: the walk cannot be completed), which the results will say. |
| 27 | concrete_domain | **fitted as-is** | one route; `navigate` is a relaunch. |
| 28 | concrete_domain | **fitted as-is** | every element read off the dumps; View ids throughout except the Compose tab tags, which are bare resource-ids. |
| 29 | concrete_domain | **adjusted** | typed strings and taps as the template has them, plus a `selectors:` block for `type_into` targets (the reminder dialog has two text fields and `enter_text` only reaches the first). |
| 30 | concrete_domain | **fitted as-is** | two anchors, each present on its screen and absent on the other (dumps 01/21 vs 02/29). |
| 31 | type_description | **fitted as-is** | MedicineId, DoseAction, Validity with their rendered strings. |
| 32 | type_description | **adjusted** | no per-item value to verify against the store; the authoritative figure is the dose (`Dose.med_a` = "1"), which is the band's unit. |
| 33 | type_description | **adjusted** | `StockBand` with `role: band`, read from the card, unit from the dose; `DoseState` with `role: enum`, read from the state button's content description ("Please wait…", "Taken", "Skipped"); `WriteStatus` without a role, as the app shows no status. |
